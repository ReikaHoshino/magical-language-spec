# 魔術言語仕様 v0.2

v0.1を基礎に、MIRをパース可能な形式言語として扱い、ASTからMIRへの typed elaboration を導入する。

## 1. コンパイラ環境

`(Γ, Δ, Λ, Π)` を用いる。

- `Γ`: 型環境
- `Δ`: 量・次元環境
- `Λ`: Lease環境
- `Π`: 権限環境

## 2. 双方向型検査

```text
Γ;Δ;Π ⊢ e ⇒ T
Γ;Δ;Π ⊢ e ⇐ T
```

前者は型推論、後者は要求型への適合検査。

数値 `1000 kg m^2 s^-2` だけでは Energy/Torque の意味型を一意に決めない。利用文脈から意味型を精緻化する。

## 3. 次元

次元ベクトル順序:

`(kg,m,s,A,K,mol)`

代表例:

```text
Mass        = (1,0,0,0,0,0)
Length      = (0,1,0,0,0,0)
Temperature = (0,0,0,0,1,0)
Velocity    = (0,1,-1,0,0,0)
Momentum    = (1,1,-1,0,0,0)
Energy      = (1,2,-2,0,0,0)
Power       = (1,2,-3,0,0,0)
Charge      = (0,0,1,1,0,0)
```

加減算は意味型・次元双方の一致を要求。積/除算は次元ベクトルを加減する。

## 4. MIRの骨格

```text
spell HeatTransfer {
    let source : Ref<Region> = resolve<Region> @water;
    let sink   : Ref<Region> = resolve<Region> @air;

    let ch : Channel<Energy> =
        channel<Energy>(source -> sink, strength = 1.0);

    transfer ch, 1000 kg m^2 s^-2;
}
```

## 5. RESOLVE / OBSERVE

`RESOLVE<T>` は `Ref<T>` を返す。一意性は実行時の証明義務になりうる。

`OBSERVE` は `Measurement<Q>` を返し、観測精度は観測量と同次元である必要がある。

## 6. CHANNEL

`Channel<Q>` の端点型・無次元strength・権限を静的に検査する。

距離二乗コストは型ではなくPREPARE時の資源条件である。

## 7. TRANSFER

概念的規則:

```text
Channel<Q> × Quantity<Q> → Unit
```

意味型・SI次元・`Transfer<Q>` 権限が一致しなければならない。

「熱」は独立した保存量型とせず、`Energy` の transfer mode `Thermal` とする。力も輸送せず、運動量を輸送する。

## 8. RECONFIGUREと証明義務

`RECONFIGURE` は適切なWrite Leaseを要求し、Mass/Charge/Energy balance等の証明義務を生成する。

`invariant` は世界全体の保存則解除ではなく、対象領域の局所的不変条件を指定する。

## 9. Effect system

命令は効果集合を持つ。

```text
OBSERVE              ! {Read}
TRANSFER<Momentum>   ! {Transfer<Momentum>}
RECONFIGURE          ! {Write<BondStructure>}
```

術式の推論effect `ε` は `ε ⊆ Π` を満たす必要がある。

## 10. CONSTRAIN

predicateは単純Boolではなく、真偽と誤差量を持つ制御条件として扱う。toleranceは誤差と同次元。

概念型:

`Controller<Target, ErrorDimension, EffectSet>`

必要effectを提供できないactuatorしかない場合は `EffectError`。
