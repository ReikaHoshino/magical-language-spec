# 魔術言語仕様 v0.10.0

v0.8.0 Minimal Local Evaluatorとv0.9.0 Sandboxed Runtimeをstable-core候補として、**versioned conformance foundation**へ編成する最初のpost-v0.9 stabilization release snapshot。

v0.10.0はv1.0 RCではない。Issue #40の5 readiness gateをすべて満たすまで追加のv0.x stabilization releaseを許容する。

## 1. Release milestone

v0.10.0で初期conformance classをversionedに定義する。

```text
Core-1.0
Evaluator-1.0
Adapter-lat-1.0
Runtime-1.0
```

conformance claimはrepository unittestの存在だけから自動生成しない。

```text
repository test != conformance case merely by existing
stable case ID != test method name
implementation output != conformance truth
```

machine-readable ownership:

```text
schemas/conformance-manifest.schema.json
conformance/manifest.json
schemas/conformance-coverage.schema.json
conformance/rule-coverage.json
```

## 2. Stable case identity / traceability

各required conformance caseはstable project IDを持ち、少なくとも:

- applicable conformance class;
- current normative document + exact heading;
- executable test locator;
- fixture locator where applicable;
- expected outcome;

を明示する。

既存canonical identityの意味が変わらない場合は再利用する。v0.10では少なくとも:

```text
WB-TEST-006
WB-TEST-008
```

を新しいv0.10専用IDへgratuitously renumberしない。

reverse rule coverage inventoryは、candidate classのrequired caseをすべてcovered ruleへ結び、class breadth外のruleは`deferred`または`non-executable`と理由付きで記録する。

```text
missing test != silently covered
explicit deferral != conformance pass
```

## 3. Conformance class lifecycle

v0.10 manifestのclass lifecycle:

```text
candidate
blocked
```

candidate classはrequired caseを全てpassして初めてclaim可能。

blocked classのtestをmeasurement目的で実行しても:

```text
blocked baseline all green != class conformance
```

reference runnerの`--include-blocked`はmeasurement専用でclass statusを変更しない。

Issue #55はPR #57で解決済みであり、v0.10の`Runtime-1.0`はcandidateである。

## 4. Core-1.0 candidate

Core-1.0は少なくとも:

- specification ownership / representation separation;
- exact six-operation MKI boundary;
- Unknown / Estimate / PlanningAssumption separation;
- SemanticFingerprint boundary;
- compatibility result/admission boundary;
- registry/index/world revision-domain separation;

をrequired candidate surfaceとして扱う。

```text
SemanticFingerprint != artifact content_hash
Unknown != zero
WorldIndexRevision != WorldRevision
Registry metadata != Capability
```

production WorldIndex/storage algorithm、formal theorem proving、non-reference adapter breadthはCore-1.0 required implementation breadthではない。

## 5. Evaluator-1.0 candidate

v0.8 reference evaluator boundaryをstable candidateへ編成する。

public ingress:

```text
explicit LanguageAdapter<lat> source
OR
schema-valid NSR JSON/object
```

internal direct ingressではないもの:

```text
SemanticAST
TypedMIR
NormalizedIR
KernelPlan
```

required checks/evidence include:

- semantic type;
- SI dimension;
- read-only resolution/identity evidence;
- authority;
- Lease;
- conservation/accounting;
- Unknown/estimator/planning separation;
- deterministic machine-readable FeasibilityReport serialization;
- no authoritative COMMIT/world mutation.

```text
Evaluation != Execution
Feasibility != Authority grant
Estimate != Reservation
Lexical meaning != Entity resolution
```

## 6. Adapter-lat-1.0 candidate

reference Latin adapterは:

- common source normalization;
- explicit `lat` adapter dispatch;
- lexicon/morphology/verb-frame evidence;
- supported corpusのdeterministic candidate/NSR path;
- ambiguity preservation and policy behavior;

をrequired surfaceとする。

```text
AI proposal != semantic truth
Confidence != proof
automatic language detection = non-goal
```

full historical/register Latin profileとnon-Latin adapter breadthはv0.10 required surfaceではない。

## 7. Runtime-1.0 candidate — public ABI

portable MKI semantic ABIはexactly six operations:

```text
RESOLVE
OBSERVE
CHANNEL
TRANSFER
RECONFIGURE
CONSTRAIN
```

```text
generate != MKI primitive
COMMIT != MKI data-plane primitive
World Kernel interaction class != MKI primitive
```

PREPARE / revalidation / COMMIT、scheduler/time、sandbox limits、emergency stop、replay、runtime trace serializationはv0.9 foundationを継承する。

## 8. World Kernel lower semantic execution boundary

Issue #55 / PR #57でlower execution semanticsを確定した。

World Kernel interaction classes:

```text
QUERY
SAMPLE
TRANSITION
ACTIVATE
DEACTIVATE
```

これらは:

- new MKI primitiveではない;
- source syntaxではない;
- physical primitiveではない;
- numerical solver/integrator microstepではない;
- v1.0 public serialized ECIR schemaを要求しない。

implementationは内部ECIR/object/data structureを自由に持てるが、observable semanticsを維持するMUST。

## 9. Authoritative active-effect ownership

future authoritative world evolutionをcausally決めるpersistent effect semanticsはauthoritative projectionを持つ。

対象例:

```text
Transit
active Channel
Controller
DynamicsProcess / KineticProcess
```

runtime `Ω`はrealization handles、queues、caches、solver bookkeeping等を保持できるが:

```text
runtime bookkeeping != semantic active-effect ownership
```

とする。

## 10. COMMIT / lifecycle / atomicity

control-plane COMMITはadmitted initial semantic groupをcurrent evidence下でatomicにcommitする。

```text
control-plane COMMIT
!= all future consequences already occurred
```

future due discrete consequencesはcurrent scheduler `Revalidate → Commit` boundaryを通る。

invariant-sensitive loweringは`KernelAtomicGroup`としてall-or-noneに扱う。

mandatory guard failure時:

```text
no partial authoritative transition
no partial activation
```

を要求する。

## 11. TRANSFER / RECONFIGURE / CONSTRAIN

non-zero TRANSFER:

```text
source debit + Transit activation
  -- KernelAtomicGroup --> committed

in-flight accounting preserved

later destination credit + Transit settlement
  -- KernelAtomicGroup --> committed
```

continuous RECONFIGUREはadmitted Dynamics/Kinetic processをACTIVATEする。numerical integrator stepをworld ontologyへ昇格しない。

CONSTRAINはbounded Controller contractをACTIVATEする。future actuationはtarget/effect/model/resource/timing/Capability/Lease/current stateのscope内でcurrent revalidationを通る。

```text
Integrator approximation != physical law
PlannerPrediction != RuntimeSafetyGuarantee
```

## 12. Emergency stop / DEACTIVATE

DEACTIVATEまたはemergency stopはadmitted effectのsettlement/terminationを表し、既にcommitted/accountedな過去stateを削除するrollbackではない。

```text
Emergency-stop requested != stopped
Stopped != rolled back
DEACTIVATE != rollback
```

## 13. Compatibility admission

各domain compatibility decisionは引き続きowning profileが生成する。

aggregate v0.10 reference admission:

```text
all required = Compatible   -> Allowed
any required = Incompatible -> Denied
required missing/Undetermined -> Indeterminate / not admitted
```

aggregate gateはrevision/hash/tagからcompatibilityを再計算しない。

```text
CompatibilityAdmission != Capability
CompatibilityAdmission != Lease
CompatibilityAdmission != trust proof
SemanticFingerprint != artifact content_hash
```

## 16. Explicit non-goals / carry-over

v0.10.0は次を保証しない:

- v1.0 RC readinessの自動成立;
- public stable ECIR serialization;
- one internal storage layout;
- scheduler/integrator solver microstep semantics;
- standalone wheel/sdist resource portability (#60);
- production distributed runtime;
- production WorldIndex/storage engine;
- non-Latin adapter breadth;
- automatic language detection / GUI;
- exhaustive physical/chemical/biological models;
- high-performance parallel runtime;
- full theorem proving。

これらのうちv1.0 guaranteeに必要と実証された項目だけをIssue #40で後続v0.x blockerへpromotionする。
