# 魔術言語仕様 v0.8.0

v0.7.3のSemanticFingerprint V1を基礎に、pre-v0.8で固定したregistry/runtime-profile/name-resolution/security/source-normalization/common-values/compatibility/Latin-adapter/scope/ambiguity/planning/estimator/canonical-conformance contractをrelease scopeへ取り込み、最初のusable reference implementationとして**Minimal Local Evaluator**を提供する。

## 1. Release milestone

v0.8.0はexecution runtime releaseではない。

```text
supported input
→ semantic pipeline
→ KernelPlan
→ assessments
→ FeasibilityReport
→ STOP
```

world mutationまたはCOMMIT executionは行わない。

中心境界:

```text
Evaluation != Execution
Estimate != Reservation
Feasibility != Authority grant
Unknown != zero
Language-specific parse != NSR
NSR != SemanticAST
SemanticAST != TypedMIR
SemanticFingerprint != artifact content_hash
Lexical meaning != Entity resolution
Visibility != Authority
Registry metadata != Capability
WorldIndex != WorldState
IndexRecord != Entity
```

## 2. Public v0.8 input boundary

public ingressは次の2系統に限定する。

1. explicit `LanguageAdapter<lat>` を通るnatural-language source。
2. schema-valid NSR JSON/objectとcanonical structured NSR fixture。

```text
NaturalLanguageSource --lang lat
→ LanguageAdapter<lat>
→ NormalizationCandidateSet
→ AmbiguityPolicy
→ NSR

NSR JSON/object
→ NSR validation
```

`SemanticAST`, `TypedMIR`, `NormalizedIR`, `KernelPlan`等をstable public direct-entry contractにはしない。
automatic language detection / input-kind detectionも行わない。

一般multi-stage ingressはIssue #48へdeferする。

## 3. Evaluator pipeline

```text
supported v0.8 input
→ adapter / normalization when Latin
→ NSR validation
→ SemanticAST
→ TypedMIR minimal elaboration
→ semantic type / SI dimension validation
→ read-only resolver / SemanticRegistry evidence
→ KernelPlan construction
→ planning inference / generation planning
→ Energy / resource / timing estimation
→ authority / Lease / conservation assessment
→ FeasibilityReport validation
```

SemanticASTとTypedMIRを同一stageへcollapseしない。

## 4. SemanticFingerprint V1

v0.7.3で固定したalgorithmを変更しない。

```text
SemanticFingerprintV1(NSR)
  = SHA-256(
      UTF-8(
        JCS(CanonicalSemanticProjectionV1(NSR))
      )
    )
```

representation:

```text
sf:v1:sha256:<64 lowercase hexadecimal digits>
```

artifact `content_hash`, `registry_hash`等へこのalgorithmを一般化しない。

## 5. Reference Latin adapter

`lat`は唯一のv0.8 source→NSR reference adapterである。

```text
Calorem ab aqua ad aerem transfer.
```

はsource normalization、lexicon/morphology/frame evidence、ambiguity policyを通ってNSRへ到達する。

`eng`を含む非reference adapterの実装済み/適合済み主張は行わない。

## 6. Ambiguity

```text
StrictReject
InteractiveResolve
ContextualDeterministic
LegacyPermissive
```

pre-v0.8で固定したdeterministic ranking/replay trace contractを維持する。
`InteractiveResolve`で外部選択が必要な場合、evaluatorは勝手にcandidateを選ばず`Indeterminate`で停止可能とする。

## 7. SemanticAST / TypedMIR

v0.8 evaluatorはsupported subsetについてlanguage-independent `SemanticAST` とtyped/dimensioned `TypedMIR`を内部生成する。

```text
semantic type equality != SI dimension equality
```

両方を独立に検査する。

schema-validだが未実装semantic subsetの場合、意味を発明せず`Indeterminate` / `UnsupportedSemanticSubset`とする。

## 8. Read-only resolution / registry

SemanticRegistryとWorldIndexはv0.8 evaluatorからread-only evidence sourceとして利用する。

```text
SelectorProposal
→ WorldIndex candidate evidence
→ authoritative revalidation requirement
```

index candidateをauthoritative `Ref`へ昇格させない。
registry metadataからCapabilityを生成しない。

production storage/spatial query engineは本release外である。

## 9. MKI / KernelPlan

MKI data-plane primitiveは引き続き6個だけである。

```text
RESOLVE
OBSERVE
CHANNEL
TRANSFER
RECONFIGURE
CONSTRAIN
```

v0.8 KernelPlanへ第7 primitiveを導入しない。
`COMMIT`はcontrol-plane boundaryであり、v0.8 evaluatorは実行しない。

## 10. Unknown / Estimate / PlanningAssumption

pre-v0.8 Issue #34 contractを実装する。

```text
Unknown
!= Estimate
!= PlanningAssumption
!= observed/authoritative truth
```

source/NSR Unknownを採用planning valueで上書きしない。

canonical water-ballのomitted terminalはsource上:

```text
Unknown(MissingArgument)
```

のまま保持する。

profileが許可する場合のみ、50 m horizonを別の`PlanningAssumption`として`PrepareBound`で採用する。
`MustResolve` obligationを推定で弱めない。

## 11. Plan selection

candidate optimizationの既定順序:

1. source fidelity。
2. mandatory obligations。
3. feasibility。
4. bounded exact Energy objectiveによる比較。

explicit semanticsを変更したcheaper planは選択しない。
mandatory obligation失敗を低Energyで相殺しない。

## 12. Estimator profile

Energy/resource/timing estimatorのmodel identity/revision/coefficient ownershipはpre-v0.8 Issue #17 contractに従う。

synthetic reference profileはconformance専用でありworld constantではない。
canonical synthetic Energy total:

```text
200 J
```

Energy breakdownには少なくともphysical workとcontrolを別componentとして保持する。
required estimator unavailable時は値を捏造せず`EstimatorModelUnavailable` / `Indeterminate`とする。

## 13. Authority / Lease / conservation

Estimator outputは次を満たす証明にならない。

- semantic type proof;
- identity/revalidation evidence;
- Capability;
- Lease;
- conservation proof;
- sandbox safety。

canonical pathではそれぞれのcanonical evidenceを独立に評価する。
Capability/Lease等の明示失敗は`Infeasible`となる。

## 14. Canonical water-ball — WB-CANON-001

canonical source fidelity constraints:

```text
material             water
mass                 50 kg
radius               0.01 m
distance             3 m
initial velocity     0 m/s
acceleration         50 m/s^2
trajectory           horizontal-forward
terminal             Unknown(MissingArgument)
```

canonical authoritative English surfaceはprovenance/source-fidelity evidenceとして保持するが、v0.8はEnglish adapterを実装済みとは主張しない。

evaluatorはselected structured NSRからcanonical pipelineへ入る。

selected canonical plan:

```text
wb:plan:transfer-reconfigure
```

KernelPlan:

```text
RESOLVE
OBSERVE
CHANNEL
TRANSFER
RECONFIGURE
CONSTRAIN
```

horizontal trajectoryのためgravityをworld modelから削除せず、`CONSTRAIN`とcontrol Energy costで扱う。

canonical resultはworld mutationではなくplan/reportのみである。

TypeError

  --source "Calorem ab aqua ad aerem transfer." \

## 19. Non-goals / v0.9 handoff

v0.8.0は以下を実装しない。

- authoritative mutable WorldState;
- COMMIT execution;
- production WorldIndex/storage/spatial engine;
- full scheduler/integrator runtime;
- general direct SemanticAST/TypedMIR/NormalizedIR ingress;
- automatic language/input-kind detection;
- non-reference language adapter breadth;
- renderer breadth;
- performance optimization。

次releaseの中心はIssue #37 — v0.9 Sandboxed Runtime。
v0.9はv0.8のTypedMIR / KernelPlan / PreparedPlan / FeasibilityReport境界を再利用し、第二compiler pathを作らない。

release後の変更はcurrent `reference/` と次versionで行い、本snapshotを遡及変更しない。
