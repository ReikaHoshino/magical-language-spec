# 魔術言語仕様 v0.5.2

v0.5.1を基礎に、未確定だった式評価・selector・量trait・光学量・ラテン語校訂・操作意味論の骨格を正式化する。

## 1. 式の優先順位

MIRの式は次の強さで結合する。上ほど弱い。

```text
or
and
== !=
< <= > >=
+ -
* /
unary: - not
^
primary
```

`^` は右結合、それ以外の算術二項演算は左結合とする。

例:

```text
-a^2      == -(a^2)
a^b^c     == a^(b^c)
a+b*c     == a+(b*c)
```

比較演算の連鎖 `a < b < c` は暗黙展開せず、必要なら `a < b and b < c` と書く。

## 2. Selector

selectorはEntityそのものでもRefでもなく、RESOLVEへ渡す検索記述である。

```text
Selector<T>
```

代表カテゴリ:

```text
SymbolicSelector<T>   // @stone
SpatialSelector<T>    // sphere(...), within(...)
RelationalSelector<T> // nearest(...), relative_to(...)
FilteredSelector<T>   // where(...)
```

selectorの評価はRESOLVE時点で行われる。selectorを保存して後でRESOLVEすればlate binding、RESOLVE結果の `Ref<T>` を保存すればearly bindingとなる。

空間selectorは座標系 `Frame` を持つ。

```text
WorldFrame
EntityFrame<Ref<Entity>>
AnchorFrame<Ref<Anchor>>
```

Frameを一意に決定できない空間selectorは静的またはPREPARE時に拒否する。

## 3. Transferable / Conserved

`Transferable` と `Conserved` は継承関係ではなく直交したtraitである。

```text
Q : Transferable
```

はMKIが `Channel<Q>` を実装できることを示す。

```text
Q : Conserved
```

は通常の閉じた系で保存則の対象となる意味型であることを示す。

一般的な保存量TRANSFERには両方を要求する。

```text
Q : Transferable & Conserved
```

例:

```text
Energy    : Transferable & Conserved
Momentum  : Transferable & Conserved
Charge    : Transferable & Conserved
Temperature       : neither
LuminousIntensity : neither
```

trait付与は次元から自動推論しない。

## 4. Radiometric / photometric quantities

`cd` を含む測光量と、エネルギーを基礎とする放射量を分離する。

放射量:

```text
RadiantEnergy     : kg m^2 s^-2
RadiantFlux       : kg m^2 s^-3
RadiantIntensity  : kg m^2 s^-3   // per solid angle; sr is dimensionless
Irradiance        : kg s^-3
Radiance          : kg s^-3
```

測光量:

```text
LuminousIntensity : cd
LuminousFlux      : cd            // cd sr; sr is dimensionless
Illuminance       : cd m^-2
Luminance         : cd m^-2
```

同次元でも意味型は別である。

放射量から測光量への変換は波長分布と観測者モデルを必要とし、暗黙castを禁止する。

## 5. Operational semantics skeleton

実行構成を概念的に:

```text
C = <Σ, H, Ω, P>
```

とする。

- `Σ`: 現在世界状態
- `H`: 確定履歴/因果グラフ
- `Ω`: ランタイム状態（SpellInstance, Lease, Channel, queue等）
- `P`: 評価中のMIR項

small-step遷移:

```text
C -> C'
```

純粋式評価は `Σ` と `H` を変更しない。

MKI/control-plane操作は、型・effect・権限・Lease・証明義務を満たした場合のみ対応する状態遷移を発生させる。

`PREPARE` は不可逆な物理変更を行わず、tentativeな解決・予約・Lease取得等を `Ω` に保持できる。`COMMIT` 後に発生した物理Eventは原則ロールバック不能。

## 6. Async causality

`TRANSFER` は `TransferHandle<Q>` を返す。

開始Eventと到着Eventを分離し、到着待ち:

```text
await tx;
```

により後続処理との happens-before を確立する。

輸送中は `Transit<Q>` が量を保持し、source + transit + destination の保存則を満たす。

## 7. Magical Latin editorial policy

例文の意味構造とラテン語表層形を分離する。

- `canonical`: 現行標準例
- `provisional`: 意味対応は有効だが語彙・語順を校訂可能
- `deprecated`: 履歴保存のみ。新規資料では使わない
- `fragment`: 構文機能のみを示す断片

ラテン語校訂によって表層形を変更しても、意味構造が同一なら例文IDを維持できる。意味構造/MIR対応が変わる場合は新IDを発行する。

時代区分や語彙の真正性は `register` と注記で管理し、古典ラテン語でない技術語を無理に古典語として扱わない。

## 8. v0.5.2の位置づけ

新しいMKI基本命令は追加しない。v0.5までの世界モデル・権限モデル・時間因果モデルを維持し、その解釈を形式化する整備リリースである。
