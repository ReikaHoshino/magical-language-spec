v0.10.0 Conformance Foundationへ、v1.x compatibility / deprecation / exact migration guaranteeと
required reference-path coverageをversioned conformance evidenceとして追加するstabilization release snapshot。

v0.11.0はv1.0 RCではない。Issue #40の全5 readiness gateが証明されるまでIssue #38を解放しない。

## 2. Compatibility guarantee

v1.x candidate stable scopeを`RequiredCore / StablePublic / OptIn / Experimental /
ImplementationInternal`へ分類する。versionはchange classを示すが個別compatibilityを決めない。

```text
release version policy != domain compatibility algorithm
version ordering != compatibility proof
same major != automatic compatibility
```

patchはstable contractを再解釈・削除しない。minorはbackward-compatible additiveまたはexplicit
opt-in surfaceを追加できる。breaking required-core changeはnew majorまたはseparately versioned
explicit opt-in contractを要求する。

## 3. Deprecation and migration

deprecationはowner、affected exact contract、deprecated release、earliest removal major、replacement
またはrationaleをmachine-readableに持つ。

migration selectionはdomain、exact source/target identity/revision/profileだけで行う。revision ordering、
hash、SemanticFingerprintからpathを推測しない。

```text
exact selection
→ named transformation identity/revision
→ target schema validation
→ target profile compatibility re-evaluation
→ separate trust/authority/admission gates
```

missing/ambiguous path、invalid output、incompatible/undetermined result、wrong target profileはfail closed。

```text
migration success != compatible by itself
migration success != trusted
migration success != authorized
migration success != admitted
```

## 4. Required reference-path compatibility coverage

`conformance/compatibility-coverage.json`は次の7 domain-owned profileをrequired inventoryとして持つ。

```text
SpecVersion
Schema
SemanticRegistry
RuntimeProfile
LanguageAdapter
SemanticFingerprint
WorldIndex
```

inventoryはNSR、SemanticRegistry、WorldIndex、RuntimeProfile、LanguageAdapter-lat、
SemanticFingerprintV1、FeasibilityReport、RuntimeExecutionTrace、ConformanceManifestの必要domainを
列挙する。domain algorithm/resultをinventory自身が発明しない。

## 5. Versioned conformance promotion

Core-1.0 required casesへ次を追加する。

- reference-path compatibility coverage completeness;
- additive minor evolution / forbidden patch reinterpretation;
- same-major deprecation removal rejection;
- successful exact migration and mandatory postconditions;
- missing / ambiguous migration rejection;
- invalid migrated output rejection;
- post-migration incompatibility rejection;
- wrong target profile rejection;
- migration resultがauthority/trust/admissionを生成しないこと。

各caseは`conformance/manifest.json`でstable ID、normative heading、test/fixture evidenceを持ち、
`conformance/rule-coverage.json`からreverse mappingされる。

## 6. Packaging and release boundary

Issue #60 / PR #62のsingle-authoring-source resource projectionを維持し、release gateはclean checkout、
editable install、isolated wheel、isolated sdistでschema/conformance/evaluator resource resolutionを検証する。

historical `spec/v0.10.0.md`以前は変更しない。

## 7. Preserved invariants

```text
shared metadata rules != shared compatibility algorithm
hash mismatch alone != incompatibility
SemanticFingerprint != artifact content_hash
SemanticFingerprint profile mismatch != semantic equality proof
WorldIndexRevision != WorldRevision
adapter ID != external language tag
compatibility evidence != Capability or Lease
public serialized ECIR remains a non-goal
```

## 8. v1.0 readiness boundary

v0.11.0はCompatibility Guarantee gateへversioned evidenceを提供する。他gateの最終no-waiver audit、
complete stable-surface conformance certification、final reproducible release rehearsalはIssue #40に残る。

```text
v0.11 release success != Issue #40 complete
v0.11 release success != Issue #38 READY
```
