# 魔術言語仕様 v0.6

v0.5.2を基礎に、集合Selector、複合TRANSFER payload、semantic/transfer registry、observer modelを正式化する。

## 1. 目的

v0.6の中心原則は次の通り。

```text
Selection != live world view
TransferKind != scalar QuantityKind
Payload != Quantity in general
Registry metadata != spell authority
Radiometric quantity != photometric quantity
```

MKIのdata-plane基本命令は引き続き `RESOLVE / OBSERVE / CHANNEL / TRANSFER / RECONFIGURE / CONSTRAIN` の6つとし、新しい世界作用primitiveは追加しない。

## 2. 集合Selector

MKI `RESOLVE<T>` は引き続き単一の `Ref<T>` を返す。

複数対象を扱う高級APIとして:

```text
select<T>(
    selector,
    limit = N,
    order = <OrderSpec>
) -> Selection<T>
```

を導入する。

`Selection<T>` はlive collectionではなく、ある時点で得た有限snapshotである。

```text
Selection<T> {
    refs          : Vec<Ref<T>>
    selected_at   : Instant
    index_revision
    order
    truncated     : Bool
}
```

`limit` は必須。世界作用を伴う無制限集合探索は禁止する。

候補集合が変化してもSelectionは自動更新されない。継続監視にはevent subscriptionまたはCONSTRAIN等を用いる。

## 3. Selectionの決定性

同じworld snapshot、同じselector、同じframe、同じvisibility policy、同じorderなら、同じSelectionを返すことを目標とする。

順序が意味を持つ場合は `OrderSpec` を明示する。

例:

```text
nearest_first(origin)
entity_id_order
stable_index_order
```

順序未指定で複数候補のうち一つを暗黙選択してはならない。

## 4. TransferKindとPayloadOf

v0.5.2までの単純なTRANSFER規則:

```text
Channel<Q> × Quantity<Q>
```

を、一般形:

```text
Channel<K> × PayloadOf<K>
    -> TransferHandle<K>
```

へ拡張する。

`K` はtransfer kindである。

単純量では:

```text
PayloadOf<Energy>   = Quantity<Energy>
PayloadOf<Momentum> = Quantity<Momentum>
PayloadOf<Charge>   = Quantity<Charge>
```

となり、既存コードは意味上互換。

## 5. MatterPayload

Matterは単一scalar量ではないため:

```text
PayloadOf<Matter> = MatterPayload
```

とする。

概念型:

```text
MatterPayload {
    composition      : Composition
    amount            : Quantity<AmountOfSubstance>
    momentum          : Quantity<Momentum>
    internal_energy   : Quantity<Energy>
    charge            : Quantity<Charge>
    thermodynamic_state
    structure_descriptor?
}
```

`composition` は化学種/成分のinventoryであり、それ自体を普遍的保存量とはみなさない。化学反応・核反応等によってspecies identityは変化しうる。

Matter TRANSFERは最低限Energy/Momentum/Charge等のcoupled accountingを満たさなければならない。

## 6. ConservationProfile

transfer kindごとに、輸送時に追跡すべき保存ledgerを指定する。

```text
ConservationProfile<K> {
    ledgers : [ ... ]
    local_invariants : [ ... ]
}
```

例:

```text
Energy   -> [Energy]
Momentum -> [Momentum, Energy]
Charge   -> [Charge, Energy]
Matter   -> [Energy, Momentum, Charge]
```

ここでMomentum転送にEnergy accountingが必要なのは、現実の物理過程として仕事・運動Energy変化を無視できない場合があるためであり、`TRANSFER<Momentum>` がEnergyそのものをpayloadとして輸送するという意味ではない。

## 7. Transferable / Conserved / CompositePayload

traitは直交する。

```text
Transferable
Conserved
ScalarPayload
CompositePayload
Observable
```

例:

```text
Energy   : Transferable & Conserved & ScalarPayload & Observable
Momentum : Transferable & Conserved & ScalarPayload & Observable
Charge   : Transferable & Conserved & ScalarPayload & Observable
Matter   : Transferable & CompositePayload & Observable
Temperature : Observable
```

`Matter` 自体をscalar conserved quantityとして扱わない。

## 8. SemanticRegistry

コンパイラとMKIが意味型/transfer kindの契約を共有するため、read-onlyなregistryを定義する。

概念entry:

```text
SemanticEntry<K> {
    id
    category
    dimension?
    payload_type?
    traits
    conservation_profile?
    allowed_modes
    endpoint_requirements
    observer_properties
}
```

例:

```text
Energy {
    dimension = kg m^2 s^-2
    payload_type = Quantity<Energy>
    traits = [Transferable, Conserved, ScalarPayload, Observable]
    allowed_modes = [Thermal, Radiative, Mechanical, ...]
}
```

registryへ登録されていることは、その術式に権限があることを意味しない。

```text
Registry metadata != Capability
```

## 9. Registry identity

compiled spellは、意味型解釈の前提となるregistry revision/hashを記録できる。

```text
CompiledSpell {
    ...
    registry_hash
}
```

実行カーネルと非互換なら:

```text
RegistryMismatch
```

としてPREPARE前またはロード時に拒否する。

これにより同じ `Energy` という文字列へ別意味を割り当てた処理系で古い術式を誤実行することを防ぐ。

## 10. ObserverModel

radiometric quantityからphotometric quantityへの変換にはobserver modelを要求する。

```text
ObserverModel<In, Out> {
    id
    response(axis)
    domain
    normalization
}
```

スペクトル測定型:

```text
Spectrum<Q, Axis>
SpectralMeasurement<Q, Axis>
```

高級純粋関数:

```text
photometric(
    spectral : SpectralMeasurement<RadiometricQ, Wavelength>,
    observer : ObserverModel<RadiometricQ, PhotometricQ>
) -> Measurement<PhotometricQ>
```

これは単位castではない。

## 11. ObserverModelの純粋性

既に取得済みのspectral measurementとobserver modelからphotometric値を計算する処理はpure functionである。

一方、スペクトルを世界から取得する行為はOBSERVE effectを持つ。

```text
OBSERVE spectral_radiance
    -> SpectralMeasurement<...>

photometric(measurement, observer)
    -> pure computation
```

## 12. Snapshotとstaleness

`Selection<T>` は取得時点の参照集合を保持する。各 `Ref<T>` はv0.4のEntityID/revision規則に従う。

Selection作成後にEntityが終了した場合、その要素の使用時に `StaleReference` が起こりうる。

必要なら:

```text
refresh(selection)
```

ではなく、元Selectorを再評価して新しいSelectionを作る。Selection自身をlive objectへ変化させない。

## 13. エラー追加

Compile / elaboration:

```text
PayloadTypeError
UnboundedSelectionError
ObserverModelTypeError
```

Load / PREPARE:

```text
RegistryMismatch
UnsupportedTransferKind
AccountingProfileError
```

Runtime:

```text
SelectionTruncated   // 原則はflag/Resultとして扱い、policyによりerror化可能
SpectralObservationFailure
```

## 14. 既存原則との整合

```text
Selector != Ref
Selection != live query
Reference != Identity != Authority != Ownership != State
Dimension equality != Semantic type equality
Transferable != Conserved
PayloadOf<K> != Quantity<K> in general
```

Restore/Rewind、IdentityPolicy、Lease、async TRANSFERの既存意味論は変更しない。
