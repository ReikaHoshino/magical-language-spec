# 魔術言語仕様 v0.9.0

v0.8.0 Minimal Local Evaluatorの単一frontend/planning pathを維持したまま、最初の実行可能な**Sandboxed Runtime**を追加するrelease snapshot。

## 1. Release milestone

v0.9.0はreal-world execution releaseではない。deterministicなin-memory sandbox/test WorldStateだけをauthoritative execution targetとする。

```text
supported v0.8 input
→ LocalEvaluator
→ FeasibilityReport / TypedMIR / KernelPlan
→ PREPARE
→ Revalidate
→ COMMIT
→ MKI sandbox runtime
→ Σ' + H' + Ω' + P'
```

v0.8とは異なりCOMMITを実装するが、外部hardware/network/worldへの作用は行わない。

## 2. Single compiler path

v0.9 runtimeはsource/NSR parser、SemanticAST elaborator、TypedMIR compiler、plannerを再実装しない。

```text
v0.8 evaluator output
→ v0.9 runtime
```

をMUSTとする。

```text
Evaluation != Execution
Feasibility != Authority grant
PREPARE success != COMMIT permission
```

## 3. Runtime configuration

reference runtimeは実装上も次を分離する。

```text
C = <Σ,H,Ω,P>
```

- `Σ`: authoritative sandbox WorldState。
- `H`: committed Event history。
- `Ω`: scheduler、channel、reservation、runtime profile等のruntime state。
- `P`: current process / PreparedPlan lifecycle state。

```text
WorldIndex != WorldState
IndexRecord != Entity
```

## 4. PREPARE / PreparedPlan

PREPAREはv0.8 reportからreversible `PreparedPlan`を構成する。

保持するもの:

- TypedMIR / KernelPlan。
- source world revision / WorldIndex revision。
- resolution/state-revision evidence。
- Capability / Lease evidence。
- conservation/accounting evidence。
- runtime profile identity/revision。
- PlanningAssumption binding。
- bounded resource reservation intent。

PREPAREだけではauthoritative `Σ` / `H`を変更しない。

## 5. Revalidate / COMMIT

COMMIT直前に最低限:

- world revision。
- entity state revision evidence。
- RuntimeProfile identity/revision。
- Capability activity。
- Lease activity。
- accounting/conservation evidence。
- emergency-stop fence。

を再検証する。

失敗したmandatory checkをv0.8 estimateやplanner predictionで代替してはならない。

supported subsetのCOMMITはatomicに扱い、mutation中のfailureではpre-COMMIT sandbox configurationを復元する。

## 6. MKI data plane

data-plane primitivesは引き続き6個だけである。

```text
RESOLVE
OBSERVE
CHANNEL
TRANSFER
RECONFIGURE
CONSTRAIN
```

```text
generate != MKI primitive
COMMIT != MKI data-plane primitive
scheduler phase != MKI primitive
integrator != MKI primitive
replay != MKI primitive
```

v0.9 canonical executionは上記6 operationをv0.8 KernelPlanの順序で実行する。

## 7. Control plane

reference implementation subset:

```text
ACQUIRE
COMMIT
RELEASE
ABORT
```

ACQUIREは既存authoritative Capability/Leaseを生成しない。admitted evidenceとreversible reservationの使用を記録する。

RELEASEはv0.9 reference pathではPreparedPlan由来reservationを解放する。authority service側のLeaseを暗黙失効させない。

`REVOKE` / `DELEGATE`は仕様上のcontrol-plane operationとして維持するが、reference implementationはv0.9でdeferする。

## 8. SandboxProfile

SandboxProfileはauthorityを追加せず、既存のsemantic/authority条件に追加制約を課す。

```text
effective operation
= semantic validity
∩ authority / Capability / Lease
∩ SandboxProfile allowance
```

reference profileは最低限:

- Energy ceiling。
- events per commit。
- microsteps per tick。
- concurrency。
- external interaction allow/deny。

をboundedにする。

non-Exact/Unknown Energyを0としてadmitしてはならない。

## 9. Scheduler / tick / physical time

logical phase order:

```text
Ingress
ContinuousAdvance
Revalidate
Commit
PublishSnapshot
Control
IndexUpdate
Dispatch
```

```text
Physical time != runtime tick
Tick execution order != causal order
```

canonical fixture:

```text
epoch        epoch:fixture:1
tick         tick:fixture:25
effective_at 2026-01-01T00:00:00Z
committed_at 2026-01-01T00:00:00.005Z
```

これらはconformance fixture値でありuniversal runtime constantではない。

## 10. Continuous integration boundary

reference `SyntheticReferenceIntegrator`はboundedなimplementation profileである。

canonical pathのzero-duration ContinuousAdvanceは:

```text
NoAdvanceRequired
steps = 0
physical_law_modified = false
```

と明示記録する。

non-zero intervalにunknown continuous process modelが存在する場合、物理法則を捏造せず`IntegratorModelUnavailable`でfail closedする。

```text
Integrator approximation != physical law
```

## 11. Canonical matter accounting

WB-CANON-001 sandbox initial accounting:

```text
source water allocation = 100 kg
accounted total         = 100 kg
```

COMMIT後:

```text
source water allocation = 50 kg
water-ball allocation   = 50 kg
accounted total         = 100 kg
```

生成物は`NewEntityFromAccountedMatter` identity policyを使う。

WorldIndex candidateやlexical proposalからidentityを捏造しない。

## 12. Planning binding / terminal semantics

source terminalは引き続き:

```text
Unknown(MissingArgument)
```

である。

v0.8が採用した50 m `PrepareBound` PlanningAssumptionをruntimeへ伝播させるが、source Unknownを書き換えない。

late unrelated entityの出現だけではPrepareBound terminalをretargetしない。

Dynamic behaviorは明示的Dynamic binding / `CONSTRAIN` semanticsを必要とする。

## 13. Horizontal trajectory control

canonical horizontal trajectoryは`CONSTRAIN` controllerとして登録する。

gravityをworld modelから削除しない。

```text
controller active = true
gravity_removed = false
```

hidden collision avoidance / planner benevolenceをruntimeへ追加しない。

## 14. Emergency stop

reference runtimeはstop fenceを実装し、新しいPREPARE/COMMITを拒否する。

```text
Requested/Fenced/Quiescing/Stopped boundary
```

のうちv0.9 supported single-process pathはfence/quiescing evidenceを実装する。

```text
Emergency-stop requested != stopped
Stopped != rolled back
```

既にCOMMITされたeffectを一般rollbackできるとは主張しない。

## 15. ABORT

pre-COMMIT failureはversioned execution traceで`ABORT`として記録できる。

少なくとも:

- StaleReference。
- AuthorityError。
- ConservationProofFailure。
- RuntimeProfileMismatch。
- EmergencyStopFence。
- SandboxLimitExceeded。
- SandboxBudgetIndeterminate。
- EventBudgetExceeded。
- MicrostepBudgetExceeded。
- IntegratorModelUnavailable。

をfail-closed boundaryとして扱う。

## 16. Replay

replayはoriginal worldを書き戻す操作ではなく、compatible profile下でclone sandboxへ同じexecutionを再構成する。

```text
DeterministicReplay != Rewind
```

replay前にexecution trace schema、runtime profile、SandboxProfile、integrator identityを検査する。

compatible executionのdeterministic state hashが一致すれば`Match`、不一致なら`Diverged`、profile/schema incompatibilityなら`Incompatible`とする。

## 17. Machine-readable execution trace

v0.9 public runtime artifact:

```text
document_kind = SandboxExecutionTrace
schema_version = 1
```

`schemas/runtime-execution.schema.json`で検証する。

Committed traceは:

- runtime / sandbox profile。
- source/result world revision。
- admission evidence。
- ACQUIRE/COMMIT/RELEASE records。
- scheduler phase records。
- IntegrationReport。
- low-level MKI runtime trace。
- committed History IDs。
- deterministic result state hash。

を保持する。

Aborted traceはfatal causeとpre-COMMIT state/history non-mutation evidenceを保持する。

## 18. Canonical WB-CANON-001 execution

explicit semantics:

```text
material         water

radius           0.01 m
distance         3 m
initial velocity 0 m/s
acceleration     50 m/s^2

```

canonical English sourceは引き続きprovenance evidenceであり、v0.9も`eng` LanguageAdapter実装済みとは主張しない。

## 19. Security boundary

untrusted source/NSR/report metadataだけでCapability、Lease、identity、registry trustを生成しない。

```text
Sandbox allowance != Capability
Visibility != Authority
Registry metadata != Capability
Replay/log input != authoritative WorldState
```

external/real-world side effectはv0.9 reference runtimeのnon-goalである。

## 20. Explicit deferrals

v0.9.0 release scope外:

- real hardware/world control。
- distributed runtime/networking。
- production persistence / WorldIndex spatial engine。
- high-performance parallel scheduler。
- exhaustive physics/chemistry/biology integration。
- OS/container-specific isolation mechanismの標準化。
- REVOKE / DELEGATE reference implementation。
- all-language adapter/renderer breadth。

後続conformance/stabilizationはIssue #40が所有する。
