# 魔術言語仕様 v0.5

v0.4を基礎に、時間・因果・イベント・非同期実行を定義する。

## 1. 世界履歴

現在状態だけでなく、履歴を保持する。

`H = (E, ≺)`

- `E`: 確定イベント集合
- `≺`: 因果的先行関係

世界全体は概念的に `(Σ,H)`。

## 2. Event

```text
Event {
    id
    kind
    actor
    cause
    started_at
    committed_at
    effects
}
```

`EventID` は再利用しない。因果グラフは通常DAG。

## 3. Time / Instant

`Quantity<Time,s>` は時間間隔、`Instant` は時点。

```text
Instant + Time    -> Instant
Instant - Instant -> Time
```

術式内部の計時にはmonotonic clockを用いる。

## 4. CHANNEL伝播遅延

距離 `d`、魔術伝播速度 `v_m` に対し:

`τ = d / v_m`

TRANSFERされた保存量は到着まで `Transit<Q>` としてCHANNEL内に存在する。

`source + transit + destination` 全体で保存則を満たす。

## 5. Async TRANSFER

```text
let tx : TransferHandle<Energy> =
    transfer ch, q;

await tx;
```

状態例:

```text
Pending
InTransit
Delivered
Failed
Cancelled
```

`await` は世界ではなく該当SpellInstanceのみを待機させる。

## 6. SpellInstance状態

```text
Prepared
Running
Waiting
Suspended
Completed
Failed
Aborted
```

## 7. Scheduling

```text
sleep 3 s;

after 3 s {
    ...
}
```

予約処理は実行時にも権限を再検査する。

## 8. Events

```text
once on EntityEntered(region) { ... }

on each EntityEntered(region) { ... }

await EntityEntered(region)
timeout 10 s;
```

イベント検知と `CONSTRAIN` による連続制御は別機構。

## 9. Leaseとsuspension

排他的Write Leaseを保持したまま `await` することは原則禁止。

`SuspendWithExclusiveLeaseError`

将来的にReservationを別機構として追加可能。

## 10. Happens-before

`await tx; B();` なら `Delivered(tx) ≺ B` を保証する。

awaitしない非同期操作間には自動的な順序保証を置かない。

## 11. Synchronization

```text
await all [tx1, tx2, tx3];

synchronize [A, B, C]
within 0.001 s;
```

「同時」は時間許容誤差内として定義する。

## 12. Historical access

```text
HistoricalRef<T>
HistoricalMeasurement<Q>
```

過去参照はread-onlyで、現在の `Ref<T>` に直接変換できない。

通常アクセス可能な履歴は EventLog / CommittedSnapshots / IdentityHistory 程度とする。

## 13. Restore / Rewind

Restore:

現在で過去と同じ/近い状態を再構成する。履歴には復元イベントが追加される。

Rewind:

確定済み因果関係 `H` そのものを書き換える。

後者は通常のRECONFIGUREでは不可能。

## 14. Temporal authority

時間遡行には概念的に次の上位Capabilityを要求する。

`Capability<History,Causality,Rewrite>`

魔力量を増やしても権限不足は解消しない。

因果循環を生じる変更は `CausalityCycleError`。

## 15. 予測と予知

`predict` は現在状態から未来を計算する純粋処理。

未来状態の直接OBSERVEは因果層アクセスであり、通常のRead権限とは別。

## 16. Event overload

`on each` は大量イベントで多数のSpellInstanceを生成しうる。

```text
max_concurrency
queue_limit
rate_limit
```

等を用いて `EventOverflow` / `ConcurrencyLimitExceeded` を防止する。
