# 魔術言語仕様 v1.0.0-rc.1

public Issue #1のrenewed exact-main no-waiver auditと、public Issue #2の明示承認・release gateに基づく
最初のformal v1.0 release candidate snapshot。

このsnapshotはv1.0 required coreを凍結する。final v1.0.0ではなく、material semantic redesignが必要に
なった場合はRCを継続せず、新しいv0.x stabilizationへ戻る。


## 3. Stable public boundary

The supported stable ingress remains:

- `LanguageAdapter<lat>` source through deterministic normalization and NSR;
- schema-valid NSR JSON direct ingress;
- deterministic evaluator output through FeasibilityReport;

SemanticAST, TypedMIR, KernelPlan, and PreparedPlan remain implementation-internal or runtime-local rather than new
portable serialized stable contracts.

## 5. Compatibility and migration guarantee

The RC freezes the v1.x contract categories:

- `RequiredCore`;
- `StablePublic`;
- `OptIn`;
- `Experimental`;
- `ImplementationInternal`.

Shared metadata rules do not create one shared compatibility algorithm. Hash, revision, release version, or
SemanticFingerprint equality alone is not admission. Exact migration requires the declared source/target contract,
named transformation, target schema validation, domain-owned compatibility re-evaluation, and separate trust/authority
checks. Migration creates no Capability, Lease, authority, trust, or semantic equality proof.

## 6. Required reference behavior

The reference implementation demonstrates:

```text
source or structured input
→ normalization / NSR validation
→ semantic validation / typed elaboration
→ resolution / registry-profile evidence
→ KernelPlan construction
→ feasibility / authority / inference / planning assessment
→ PREPARE / COMMIT in the supported deterministic sandbox
→ MKI / scheduler / replay evidence
→ deterministic machine-readable and human-readable result
```

The canonical WB-CANON-001 corpus remains the specification-owned complete end-to-end required fixture. Unsupported
semantic/runtime subsets fail closed with stable diagnostics and no authoritative partial mutation.

## 7. Experimental and deferred boundary

The following remain outside the required four-class / 65-case promise even when distributed in package `1.0.0rc1`:

- MGLS-0 / MagicalProgram-0 / SpellInstanceBundle-0 unified user workflow;
- Experimental-Arcana-0, SUCCESS-ARCANA, and DEBUG-HELL evidence;
- non-reference language adapters and renderers;
- public direct later-stage files or public ECIR;
- production WorldIndex/distributed runtime/high-performance scheduler;
- exhaustive physical, chemical, biological, medical, or theorem-proving models.

Experimental evidence cannot satisfy stable conformance claims and does not gain authority, resource, identity, or
truth from packaging or syntax.

## 8. Release verification contract

The RC gate requires:

- schema and cross-artifact release consistency validation;
- repository regression;
- all 65 required conformance cases;
- experimental suites as non-promoting regressions;
- security/runtime/replay regressions;
- editable, isolated wheel, and isolated sdist installed-entry-point smoke outside checkout;
- `git diff --check`;
- exact PR head equality with all protected checks green;
- post-merge consistency/package certification before finalization timestamp and Issue closure.

Historical `spec/v0.1.md` through `spec/v0.12.0.md` remain immutable.
