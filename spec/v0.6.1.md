# 魔術言語仕様 v0.6.1

v0.6を基礎に、MatterPayload、化学種、構造記述、反応会計を精密化する。

## 1. 中心原則

```text
Species identity != conserved quantity
Composition != structure
Matter state != Entity identity
Reaction != TRANSFER
Reaction plan != authority
Measurement of composition != kernel material state
```

MKIの基本命令は引き続き6つであり、化学反応・治療・錬金術を新primitiveとして追加しない。

```text
RESOLVE
OBSERVE
CHANNEL
TRANSFER
RECONFIGURE
CONSTRAIN
```

## 2. MatterPayloadの改訂

v0.6の単一 `amount` フィールドは混合物・組織・未知組成に対して曖昧であるため廃止し、量はComposition各entryへ持たせる。

```text
MatterPayload {
    composition          : Composition
    momentum             : Quantity<Momentum>
    internal_energy      : Quantity<Energy>
    net_charge           : Quantity<Charge>
    thermodynamic_state  : ThermodynamicState
    structure            : StructureDescriptor?
}
```

`MatterPayload` はEntity identityを含まない。

## 3. SpeciesとComposition

化学種をregistry-backed identifierとして扱う。

```text
SpeciesID
NuclideID
ElementID
MaterialClassID
```

役割:

- `ElementID`: 原子番号レベルの元素分類。
- `NuclideID`: 核種/同位体を区別する識別子。
- `SpeciesID`: 分子、イオン、原子等の化学種。
- `MaterialClassID`: steel, blood, tissue等の高級材料分類。保存ledgerには使わない。

Composition:

```text
Composition {
    entries : Map<SpeciesID, SpeciesAmount>
}

SpeciesAmount = Quantity<AmountOfSubstance>
```

離散粒子数を必要とする処理系は、exact countとAmountOfSubstance間の明示変換を高級ライブラリで提供できる。

## 4. 実状態と観測値

カーネル内部のCompositionと術式が観測したCompositionEstimateを分離する。

```text
Composition          // world/kernel state
CompositionEstimate  // measurement result
```

```text
observe target.composition ...
    -> Measurement<CompositionEstimate>
```

不十分な分解能で得たestimateを完全なCompositionとしてRECONFIGURE/TRANSFERへ暗黙使用してはならない。

## 5. StructureDescriptor

構造をCompositionから分離する。

同じH2O inventoryでも、液体・氷・結晶欠陥・微細構造は異なる。

```text
StructureDescriptor<S : StructureSchema> {
    schema_id
    schema_revision
    data : S
}
```

代表schema:

```text
MolecularTopology
CrystalLattice
Microstructure
TissueArchitecture
```

全Matterに同一の構造schemaを強制しない。

## 6. ThermodynamicState

ThermodynamicStateは状態モデルへの型付き記述であり、Temperature一値と同一視しない。

```text
ThermodynamicState<M> {
    model_id
    variables
}
```

例としてTemperature, Pressure, Phase等を含みうるが、必要変数はモデル依存。

```text
Temperature != InternalEnergy
Phase != Composition
```

を維持する。

## 7. ReactionRule

反応を高級RECONFIGURE計画として表す。

```text
ReactionRule<R : ReactionDomain> {
    id
    stoichiometry
    domain
    required_state
    products
    accounting_profile
    authority_requirements
}
```

基本domain:

```text
Chemical
Nuclear
Biochemical
Structural
```

`Biochemical` は物理法則上Chemicalの上位意味分類として実装可能だが、生体構造・触媒・局所条件等の追加proof obligationを持てる。

## 8. StoichiometryとReactionExtent

```text
Stoichiometry = Map<SpeciesID, RationalCoefficient>
ReactionExtent : Quantity<AmountOfSubstance>
```

符号規約:

```text
reactant coefficient < 0
product  coefficient > 0
```

反応extent ξに対し、理想化されたspecies量変化:

```text
Δn_i = ν_i ξ
```

ただしspecies inventoryそのものは普遍的保存量ではない。

## 9. ChemicalReactionProfile

通常の化学反応では最低限:

```text
ChemicalReactionProfile {
    conserve_nuclide_inventory
    conserve_charge
    account_energy
    account_momentum
}
```

を要求する。

元素だけで十分な系ではElement ledgerへ粗視化できるが、同位体依存反応ではNuclide ledgerを使う。

## 10. NuclearReactionProfile

核反応ではSpecies/Element/Nuclideの単純不変性を要求しない。

```text
NuclearReactionProfile
```

はregistryが定義するより低層のconservation ledgerを要求する。

v0.6.1では具体的な素粒子物理ledgerを固定せず、少なくとも:

```text
Energy
Momentum
Charge
```

のaccountingを必須とし、追加ledgerはkernel/world model contractに委ねる。

従ってChemical用ruleをNuclear domainへ暗黙昇格しない。

## 11. Reactionの実行

`REACT` というMKI primitiveは追加しない。

高級なreaction operationは概念的に:

```text
OBSERVE
-> select ReactionRule
-> acquire required Lease
-> prepare accounting/proof obligations
-> TRANSFER Energy/Momentum/etc. as needed
-> RECONFIGURE composition/structure/state
-> COMMIT
```

へ展開される。

MIRのRECONFIGUREはreaction metadataを受け取れる。

```text
reconfigure target {
    reaction = @water_electrolysis;
    extent = 2 mol;
    identity = preserve;
}
```

これは高級指定であり、compilerがReactionRuleをregistryから解決してproof obligationへ展開する。

## 12. Structure-preserving transfer

Matter TRANSFERに `structure` が含まれる場合、そのChannelは対応StructureSchemaを保存可能でなければならない。

```text
PreserveStructure<S>
```

能力をregistry endpoint/channel contractとして要求できる。

構造保存能力がないMatter channelではcomposition等を輸送できても、結晶格子・組織構造が保たれる保証はない。

## 13. Healing / 生体魔術への含意

高級 `heal(...)` はprimitiveではない。

概念的には:

```text
OBSERVE composition / structure / physiology
-> infer target state/model
-> transfer required Matter/Energy/Momentum
-> RECONFIGURE biochemical composition and TissueArchitecture
-> CONSTRAIN recovery conditions
```

となる。

人体と同じComposition/Structureを作ることはAgent identityの復元を意味しない。

## 14. Registry namespaces

SemanticRegistryを以下のlogical namespaceへ拡張する。

```text
semantic_kinds
species
structure_schemas
reaction_rules
observer_models
conservation_ledgers
```

全namespaceの互換契約をRegistryHash/required_registry_contractへ含める。
